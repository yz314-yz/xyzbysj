# 3 分钟演示视频脚本

## 视频目标

3 分钟内讲清楚“痛点 → 产品 → 核心功能 → 技术亮点 → 社会价值”，让评审快速理解岐养七日不是一次性图片识别工具，而是可离线演示、可追问、可传播的中医养生辅助系统。

## 分镜脚本

| 时间 | 画面 | 旁白 |
|---|---|---|
| 0:00-0:20 | 手机/电脑打开水墨封面，停留在“岐养七日”标题和当前时辰提示 | 现代人想养生，但不知道如何把体质、作息和日常执行连接起来。岐养七日希望把中医“治未病”的思路做成低门槛、可执行的七日方案。 |
| 0:20-0:40 | 点击“进入系统”，展示望诊采集页 | 系统支持症状选择、舌像、面相、手相采集，也可以在无图片时完全依靠本地规则引擎生成方案，答辩演示不依赖外部网络。 |
| 0:40-1:15 | 选择 2-3 个症状，上传或展示图像采集入口，填写基础信息，点击生成 | 用户只需要完成一次采集，系统会结合症状、图像特征和当前子午流注时辰生成体质方向。 |
| 1:15-1:45 | 展示结果卡、时辰建议、七日计划表 | 输出包括主要调理方向、匹配度、当前经脉提示、即时建议，以及七天的饮食、运动和作息安排。所有内容都保留“仅供学术参考，不作为医疗诊断”的边界。 |
| 1:45-2:10 | 展示 AI 养生问答，输入“晚餐怎么安排更合适？” | 如果配置了 Qwen 文本模型，用户可以基于当前方案继续追问；如果是离线演示模式，系统会明确提示对话不可用，不会伪装成模型回答。 |
| 2:10-2:30 | 展示方案分享卡下载或复制摘要 | 生成后的方案可以一键形成分享卡片，适合传播和复赛人气通道，也能帮助用户把七日计划带走执行。 |
| 2:30-2:50 | 快速切换到架构图或 README 的 TRAE 开发实践章节 | 技术上，项目采用本地规则引擎、Qwen3-VL 图像特征、Qwen 文本问答和 SQLite 历史记录，并通过 TRAE 完成需求拆解、代码实现和质量验证。 |
| 2:50-3:00 | 回到封面或结果页，显示免责声明 | 岐养七日定位为中医养生辅助与学术展示工具，帮助用户理解体质趋势和日常调理方向，但不替代医生诊断。 |

## 录制要点

- 录制比例优先 16:9，分辨率 1080p。
- 全流程尽量一次录完，减少剪辑感。
- 鼠标动作放慢，关键按钮点击前停顿 0.5 秒。
- 生成方案前准备一组稳定输入，避免现场临时选择导致画面拖沓。
- 如果没有配置模型服务，AI 问答段展示离线降级提示，强调“答辩模式可离线运行”。

## 画面检查清单

- 封面水墨背景正常渲染，没有遮挡标题。
- 采集页按钮、症状标签、上传框在画面中完整可见。
- 结果页滚动时不要过快，确保体质方向、七日计划、AI 问答、分享卡都至少停留 2 秒。
- 免责声明在结尾出现一次。
- 录制前关闭无关通知和浏览器书签栏。
