# TRAE 开发实践

## 目标

本项目使用 TRAE 作为主要 AI 辅助开发环境，围绕“中医养生辅助系统”的完整产品闭环进行迭代：需求梳理、前后端实现、测试补强、部署配置、文档和演示材料同步推进。

## 使用场景

| 场景 | TRAE 辅助方式 | 项目产出 |
|---|---|---|
| 需求拆解 | 将待改进清单按答辩风险、初赛优先级、复赛竞争力拆分 | `待改进.md` 中 P0/P1/复赛建议分层 |
| 后端工程 | 辅助拆分 controller/service/model/routes/middleware | Express 五层结构、统一错误处理中间件 |
| 安全与部署 | 检查 JWT、CORS、Helmet、Docker 非 root、健康检查 | 生产环境 JWT_SECRET 启动保护、三类 Dockerfile 安全收口 |
| AI 接入 | 设计本地规则引擎 + Qwen2.5-VL + Qwen 文本问答降级策略 | 图像特征提取、AI 养生问答、离线演示模式 |
| 前端体验 | 辅助生成 React 组件和响应式样式 | 封面页、历史详情、分享卡、对话面板、水墨背景 |
| 质量验证 | 自动规划并执行 lint/test/build/compose 检查 | Jest、Vitest、Vite build、Docker Compose config 验证 |

## TRAE 能力体现

### 1. 从需求到代码的闭环

TRAE 不只用于补代码，而是贯穿“需求文档 → 代码改动 → 测试验证 → 文档回写”。例如 P1 风险项修复时，先读取 `待改进.md`，再逐项落到配置、后端启动保护、前端交互、Prometheus 指标和系统设计文档，最后更新清单统计。

### 2. AI 双引擎架构设计

系统保留本地规则引擎作为答辩演示主路径，在 `OPEN_MODEL_BASE_URL` 为空时不依赖网络；配置 OpenAI 兼容地址后，可启用 Qwen2.5-VL 图像特征提取和 Qwen 文本问答。TRAE 辅助完成了模型可用性判断、离线降级、边界提示和测试用例。

### 3. 工程质量守门

每轮关键改动后执行：

- 后端：`npm test`、`npm run lint`
- 前端：`npm test`、`npm run lint`、`npm run build`
- 部署：`docker compose -f docker-compose.cloud.yml config --quiet`

验证结果会反向更新文档和需求清单，确保答辩材料与真实代码状态一致。

## 答辩展示建议

演示时建议突出三句话：

1. 系统不是单纯调模型，而是“本地规则引擎 + Qwen 图像特征 + Qwen 文本问答”的双路径架构。
2. 答辩模式可完全离线运行，模型不可用时系统仍能生成方案。
3. TRAE 参与了需求拆解、代码生成、测试验证和文档同步，形成可追溯的工程闭环。
